# 脚本、输入依赖与参数化工作流

沿用已有项目布局。新项目可把参数、建模源码、验证小例和生成输出分开；没有迁移需求时不重组历史目录。

## 从需求到输入文件

1. 用可序列化配置记录单位、几何、材料、区域、步、输出、工况和目标版本；标出来源及待定值。未知参数保持待定，演示值明确标为示例。
2. 共享命名表集中定义 part/instance/set/surface/material/step/job 名称；物理身份与几何选择规则分开。
3. 按依赖构造几何、材料/截面、装配、分析步、相互作用、载荷/边界、网格、输出和 job。关键阶段返回实际对象数量、标签范围和验证摘要。
4. 建模和提交分为可单独调用的动作。保存 CAE/INP 只表示生成完成，尚未求解；外部 Python 的语法检查不证明 Abaqus API 可用。
5. 参数扫描为每个工况保存输入差异、源码版本与独立输出位置。确定性命名和静态检查可以重复；是否允许重复原生求解依任务合同判断。

## INP 静态审计

- 递归解析实际 INCLUDE 依赖，保留有序关系与相对路径解析根，识别循环、缺失、重复包含和大小写差异。不要只核验主文件。
- 验证节点/单元引用、类型、连接顺序、集合、实例范围、截面指派、材料和方向；保留关键字与数据行上下文。
- 建立每步的载荷、边界、接触、激活/移除及输出状态表；检查 NEW/MOD、继承、step time/total time 和 amplitude 的真实语义。
- 映射温度/应力/场/载荷时保存源工况、时刻、坐标、单位、匹配方法、覆盖与未匹配项。几何映射不是结果可任意插值的许可。
- 自定义单元核对 USER ELEMENT 的节点数、DOF、COORDINATES、PROPERTIES/VARIABLES、UNSYMM 及实际源码；U1 等名字本身不表明物理。
- 先核对目标版本支持和关键字语义，再做已授权的小型 datacheck。datacheck 不能验证路径、材料本构、相场方程或最终科学结论。

## 新任务的最小交付

| 请求 | 应产生的可复核结果 |
|---|---|
| 普通静态参数化模型 | 参数来源、稳定区域、BC/载荷、网格与输出、可读 INP/建模脚本、静态审计；求解依实际授权 |
| 已知裂纹/界面基准 | 方法与材料数据表、作者/解析参考、载荷—位移和 K/J/G 或分离量、网格/能量比较计划 |
| 自定义相场/UEL | 泛函—变量—接口映射、独立力学/相场/状态小例、输出身份和成本估计，再进入目标模型 |
