# 执行、监控与技术恢复

本模块适用于启动/监测求解、只读 ODB 提取、数据收集或恢复。普通方案讨论和静态文件检查不强制进入原生运行流程。

## 执行前后

沿用当前任务的授权、路径、调度器和资源策略，先查已存在的意图、进程、会话与完成记录。提交前绑定模型/子程序版本、输入、工作目录、CPU、内存需求、磁盘、许可证和输出计划。solver memory 参数不是资源预留；共享机器须保护其他作业。

有一次执行约束时，为建模、datacheck、analysis、readonly export 和 collection 分别登记；未知提交结果只对账，不能再发一次“试试”。依据实际许可区分读操作、小型测试和新原生运行，已有授权不反复索取。

阶段状态应由同一作业的 scheduler、退出码、STA/MSG/DAT、console 与进程信息匹配。SSH 握手失败只表示当前状态不可观测；历史 RUNNING 不能继续当作当前事实，网络故障也不是求解失败。

## 诊断顺序

| 现象 | 先核查 |
|---|---|
| 提交无回执 | 本地提交进程、原意图、调度器确切作业身份 |
| 负特征值 | 刚体模态、约束、材料切线、接触、真实失稳；不能一概归因于 ν |
| 步长过小/畸变 | 首个错误前后的几何、单元、材料、接触、载荷路径；不是自动加稳定化/质量缩放 |
| 求解成功、导出失败 | 导出版本、变量/位置、字段类型、路径和只读生命周期；不因此重跑求解器 |
| 收集中断 | 原收集意图、已写数据、清单和同字节校验；按已验证恢复语义处理 |
| 科学不通过 | 分离物理、离散、算法、提取和验收问题，选择一个有证据价值的验证因素 |

保存 FIRSTERROR 现场及源绑定。修复影响输入、算法或工具时先在隔离小例验证，再进入独立恢复入口。不要将下载的自动重试框架直接替换有 once 约束的 controller。

只读 ODB 访问验证 readOnly、对象正常返回并关闭；可变 ODB 不做完整哈希。对已结束且稳定的只读导出，可按项目合同核验打开前后摘要、完整索引和文件 SHA，再收集。部分导出保持 diagnostic-only。

监控频率按任务记录；相同故障退避，普通健康检查不通知。关闭阶段不重入；需要新分析时新建独立入口并明确消费的是已关闭本地数据。
