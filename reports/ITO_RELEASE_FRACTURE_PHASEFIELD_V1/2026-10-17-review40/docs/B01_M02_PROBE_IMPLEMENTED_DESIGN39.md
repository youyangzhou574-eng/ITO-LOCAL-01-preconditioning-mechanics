# NEW39 离线接口探针：实现设计

本文件取代 DRAFT39 中温度零基线和回调追加日志的设计细节；原草案保留。当前只准离线实现、测试、一次独立审阅及包生成。原生用途与额度尚未批准。最终完成状态以独立交付回执为准。

## 目的与范围

在 Abaqus 2021 CPE4T 上，用一次拟议分析同时观测两个互不连接的诊断几何：单位方形 element101/node1–4；原 M02 element5817 的参考几何，重新标为 element202/node11–14。真实坐标与原标签的对应由 GEOMETRY_SELECTION39.json 绑定。公开绘图量化和原 M02 科学失败均保留。

诊断使用新 manufactured UMAT：线弹性 E=100、nu=0、厚度1、热导率1，无热膨胀；RPL 是按实际 KSTEP/NPT 控制的基函数。它不替换作者 PF-CZM UMAT，也不修改原基准。

要观测的是四个实际 NPT 的源列、四个节点温度基的导热列和接受态 TEMP/DTEMP/COORDS。NPT 只用原生标签，不预设其空间位置。两个诊断单元的数据不自动授予整个 M02 装配矩阵、最后 H 状态、峰值原因或 P1 资格。

## 八步输入和机械约束

初始所有节点温度为1。每步采用稳态 coupled、NLGEOM=NO、SEPARATED，显式 OP=NEW 重设全部机械与温度边界。

| 步 | 所有节点温度 | RPL |
|---|---|---|
| S1–S4 | 全部1 | 当实际 NPT 等于该步序号时为1，其余0 |
| T1–T4 | 1+e_j，即第j节点2，其余1 | 全部0 |

固定每单元 local nodes1/2/4 的 U1/U2 和 local node3 的 U2，保留 local node3 的 U1。离线独立刚度检查要求该自由度的弹性刚度为正，且合成约束检查确认每单元恰有一个自由机械方程。原生是否实际调用并完成该过程仍需未来 datacheck/analysis 证实，离线检查不作保证。

常量温度属于独立导热算子的零模；源与温度无关且无热膨胀，因此1的基线不改变拟观测列。该基线使 NT 与 RFL 同行打印时，真实零 RFL 不因全行全零而省略。

## 预测与可证伪区别

独立标准 Q4 预测采用参考坐标、2×2 Gauss 积分：K=sum(gradN gradN^T detJ)，源列 Q[:,q]=N(q) detJ(q)。同时保存角点积分的对角源列及节点温度采样候选。预测列按几何逆时针顺序命名，绝不直接等同 NPT1–4。

单位方形的 K 为 (1/6)*[[4,-1,-2,-1],[-1,4,-1,-2],[-2,-1,4,-1],[-1,-2,-1,4]]。Gauss 源列在四节点均非零，而角点源列为对角阵；完整观测可直接区分分布。总源、解析面积、导热常量零模、矩阵对称、重排协变和仿射温度能量有独立合成检查。没有从 M02 残量反求倍率或符号。

## 输出合同

仅计划 DAT 输出：NODE PRINT 同表 NT/RFL；EL PRINT 在积分点打印两组 STATEV，每组不超过9变量且都含非零标记 SDV1=39。未来必须由新原生日志确认输出标识和行布局；当前 RFL 运行可用性与 Fortran 编译均未验证。field/history ODB 输出频率设0，不计划新 ODB 提取。

UMAT 使用 RECURSIVE 局部变量，没有 SAVE、共享文件、追加日志或可变全局状态。STATEV 是求解器保存的状态快照，不观察所有 trial、调用次序或回滚。每步最终的源与温度基定义不依赖中间试算路径，因此该有限快照可用于计划中的受控校准；不能推广到 M02 的历史依赖。

| SDV | 内容 |
|---|---|
| 1–5 | schema39、KSTEP、KINC、NOEL、NPT |
| 6–8 | TEMP、DTEMP、TEMP+DTEMP |
| 9–11 | COORDS1、COORDS2、RPL |
| 12–16 | TIME1、TIME2、DTIME、TIME1+DTIME、状态标记1 |

Python 检查器接受带真实标签和原始数字 token 的结构化记录；它不是 Abaqus DAT 文本解析器。后续对实际版本的表头、step/increment/accepted 关联及分块合并需以原始行号/日志作为证据，不能把人工字段当独立接受态证明。

要求每类64条记录（8步×2单元×4节点或NPT），缺失、重复、非有限、未知标签、拒绝态、错误最终增量或不相容标记均拒绝。保留原始 RFL 符号和 token；十进制半末位区间用 Fraction 表示。没有符号定义时保留未资格；不翻号、不缩放、不补零。打印精度导致候选不可区分时报告 NOT_EVALUABLE。

## 离线入口与证据

run_b01_m02_probe39.py 只有 --build 入口，--submit 不被接受。五文件来源、几何、审阅和最终测试绑定逐项检查后才生成新目录；任何已存在输出目录（含孤立 intent/partial/completion/failed）均禁止重入。写入失败保留 FAILED_CLOSED。没有原生调度实现。

仅执行新39测试，历史闭合测试不重跑。新 API 缺失 RED 与真实实现缺陷 RED 分开记录；一次独立审阅后若需修复，保留定向 RED/GREEN 与最终来源绑定，不做第二次审阅。Fortran 未编译，Python 合成测试不冒充原生 ABI 或端到端运行验证。

## 预算决定（提案未生效）

当前 analysis7/32、P1used7/8、DC8/48、readonly8，无活动作业。拟观测需要1次新 datacheck 和1次新 analysis，CPU4，调度上限10分钟仅为计划上限，不承诺完成时间。原生前的实际 allocation、RAM、完整 cgroup 祖先、磁盘/配额/inode/license 门仍适用。

| 方案 | 改变 | 执行观测后的 P1 余量 |
|---|---|---|
| A（推荐） | 专加1次观测额度，P1limit8→9、analysis总limit32→33；P2/P3P4不变 | 保留1次修复验证 |
| B | 将现有最后1次 P1 修复验证额度明确改用于观测；总额度不变 | 0次 |

现有用途门要求具体 native 技术错误与单一修复预测。该探针是观测，尚不满足该用途门；因此离线包完成后需要人类选择用途/额度，不能将持续推进指示解释为预算增加。此处未批准、预留或提交任何作业。
